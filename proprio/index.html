Proprio · physical AI inference

The policy you validated. Bit for bit, faster.

Proprio runs an unmodified vision-language-action policy as a recorded device graph and proves, tick by tick, that the actions it produces are identical to the policy's own eager execution. If they are not identical, it refuses to deploy. Every run ships a Bitwise Certificate.

How

Record the tick, prove it, then deploy it.

A policy's control tick is thousands of small GPU launches driven from Python; the GPU waits for the host most of the time. Compilers close that gap by re-tracing and re-fusing the model, which picks different kernels and changes the numbers. Proprio keeps the policy's own kernels and takes a different route.

01 / RECORD

The unmodified policy

Proprio loads the checkpoint as LeRobot does, with no source edits, and records one control tick into a replayable device graph. The kernels in the graph are the kernels eager mode ran.

02 / VERIFY

Bit for bit, on held-out inputs

Replayed actions are compared with eager actions on inputs the recording never saw, with fixed noise and seeds. Not close: identical, every byte of every action chunk.

03 / GATE

Refuse what is not identical

A tick that cannot be proven identical is not deployed; Proprio falls back to the original path and says why. A non-identical tier is reported with its measured error, never as "exact".

04 / CERTIFY

A Bitwise Certificate per run

Actions, identity count, error bounds, latency, device, driver, clocks, power state, seeds and a digest, signed. The document a safety review or a customer can check with a public key.

Many robots per tick

Batch the fleet, keep every robot's answer.

Serving several robots or simulated environments per tick is the utilisation lever, but stock GPU kernels change their arithmetic with the batch size, so row i of a batched result is not what robot i gets alone. Proprio offers two tiers and certifies each row against that robot's own single-robot run.

EXACT TIER

Identical to the original policy

Every row is bit-identical to the original eager policy run for that robot alone. The stock kernels stay in place. 12.5× per robot on SmolVLA at 16 robots.

INVARIANT TIER

Identical to its own single-robot run

Batched matrix multiplications run on reduction-order-invariant kernels. Every row is bit-identical to the tier's single-robot run; its measured difference to stock eager is declared on the certificate. 14.8× per robot on SmolVLA.

UTILISATION

96% GPU busy at 16 robots

One eager SmolVLA process keeps the GPU 17% busy; a single exact replay 83%; the batched tick 96% in both tiers (Nsight, RTX 4090). 55 to 67 robots per second on one card.

Where the invariant tier's declared difference comes from: its kernels sum each dot product in a fixed order whatever the batch size, cuBLAS chooses its order per problem shape; both are correct floating-point implementations whose roundings differ by a unit in the last place per layer and compound through the network. The certificate names which implementation was validated. A 3B-parameter model is already compute-bound at one robot on this GPU, so GR00T's headline stays the 64 ms exact single-robot tick; the exact tier's per-robot execution costs more than the batch saves there.

Bitwise Certificate

What every number here stands on.

Each table row above comes from one certificate, a JSON document the engine writes after a run. The hosted certification service signs it with an Ed25519 key; anyone can verify a signed certificate with the public key.

RESULT

Identity and error

Per-tick eager and engine actions, the count of bit-identical ticks or rows, max and mean absolute error, the reference used (original eager or same-tier single-robot) and, for a non-exact tier, the declared difference to eager.

TIMING

Latency and split

p50 and p99 of both paths, the host pre- and post-processing share, the captured share of the tick, per-robot cost and batch size for rollout runs.

ENVIRONMENT

What it ran on

GPU, driver, torch build, clocks, power state and active throttle reasons at the time of the run, thread count, seeds and noise seed, weight-precision manifest, licence tier, digest and signature.
