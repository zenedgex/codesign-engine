What we are building

A residency layer beneath vLLM.

Perch sits between your clients and unmodified vLLM. Clients keep calling the same OpenAI-compatible API; vLLM keeps running your models; Perch decides which models hold each GPU at any moment.

A plugin in each vLLM engine lets a model's weights step off the GPU and back in a fraction of a second. Requests that were in flight keep their state and resume token-identical.

How

Models step off the GPU and come back in time.

Long-tail catalogs leave most models idle most of the time, yet each one holds a GPU. Perch keeps only the models that are busy on the GPU and parks the rest in host memory, without losing a request.

01 / PLACE

Decide what is awake

The agent on each node tracks every model's traffic and deadlines and decides which models hold GPU memory now.

02 / PARK

Step off in 0.33 s

When another model needs the memory, a model's weights move to pinned host memory. Its KV pool stays on the GPU.

03 / HOLD

Keep paused requests

Requests that were mid-answer pause with their state intact. Nothing is cut off and nothing is recomputed.

04 / RESTORE

Back in 0.29 s, on time

Perch restores a parked model before its paused requests would miss their first-token or per-token deadline. The answer resumes token-identical.

The release

Four parts, one per job.

Linux binaries and compiled wheels for x86_64 and aarch64 (Grace). Perch is proprietary software, offered under an evaluation licence.

perch-agent

One per GPU node

The scheduler and the OpenAI-compatible endpoint. Moves weights in and out, restores before deadlines, exports Prometheus metrics.

perch-engine

The vLLM plugin

Compiled, no fork of vLLM. Paused requests keep their state and resume token-identical.

perch-gateway

Across nodes

Routes clients to the right node, from a static list or Kubernetes pods.

perch-sim

Before you buy GPUs

Replays your own request log through the same scheduler to estimate how many models fit at your deadlines.

Try it

Fifteen minutes on one GPU node.

Download the bundle for your CPU from the latest release, install it into the Python that runs vLLM, start your engines with sleep mode, and point clients at the agent.

# install (per GPU node)
tar xzf perch-0.1.0-linux-x86_64.tar.gz && cd perch-0.1.0
sudo PYTHON=$(which python3) ./install.sh

# one vLLM server per (GPU, model), with sleep mode
VLLM_SERVER_DEV_MODE=1 CUDA_VISIBLE_DEVICES=0 vllm serve Qwen/Qwen2.5-7B-Instruct \
  --served-model-name qwen-7b --port 9001 --enable-sleep-mode --gpu-memory-utilization 0.14

# the agent, then the usual OpenAI call
perch-agent --config agent.toml --park-all
curl localhost:8080/v1/completions -H 'content-type: application/json' \
  -d '{"model": "qwen-7b", "prompt": "Hello", "max_tokens": 32}'
